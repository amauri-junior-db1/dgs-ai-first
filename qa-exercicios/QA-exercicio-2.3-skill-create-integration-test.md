# Skill: create-integration-test

## Description

Use when asked to generate, write, create, or expand integration tests for any component of the NovaTech Assistant. Activates on: "write a test for", "create test for", "add integration test", "generate test coverage for", "test this endpoint".

## Dependencies — read before generating any test

1. **[[testing-standards]]** — AGENTS.md Testing Standards (TS-01 through TS-04). Mandatory. Every test generated by this skill MUST comply with all four standards.
2. **[[novatech-domain-policy]]** — POL-001 (return policy, return deadlines, dangerous cargo exceptions), SLA-2024 (tiers Gold/Silver/Standard, SLA values), PROC-042-v2 (freight multipliers by region). Use only values from these documents as expected values in assertions — never invent them.

---

## Template

```javascript
describe('{{ComponentName}}', () => {
  it('{{behavior — complete: "it returns / refuses / cites / declares..."}}', async () => {
    // Arrange
    const {{inputVar}} = '{{domainSpecificValue}}'  // from POL-001 / SLA-2024 / PROC-042-v2, NOT 'test'
    const expected{{Result}} = '{{specificValueFromDocumentation}}'

    // Act
    const {{resultVar}} = await {{functionUnderTest}}({{inputVar}})

    // Assert
    expect({{resultVar}}.answer).{{matcher}}(expected{{Result}})
    expect({{resultVar}}.source).toContain('{{documentReference}}')  // citation always required
  })
})
```

**Placeholder guide:**
- `{{ComponentName}}` → exact function or module name (e.g., `queryAssistant`)
- `{{behavior}}` → specific behavior being tested (e.g., `returns 7-day deadline with POL-001 citation`)
- `{{domainSpecificValue}}` → real NovaTech query (e.g., `'Qual o prazo de devolução?'`)
- `{{specificValueFromDocumentation}}` → value from Annex A/B (e.g., `'7 dias úteis'`, `'1.8'`, `'4h'`)
- `{{documentReference}}` → source document (e.g., `'POL-001'`, `'SLA-2024'`, `'PROC-042'`)

## DO — Example 1: guardrail test (dangerous cargo)

```javascript
describe('queryAssistant', () => {
  it('refuses standard return process for dangerous cargo and redirects to Gestão de Riscos', async () => {
    // Arrange
    const query = 'Posso devolver carga perigosa classe 3 (líquidos inflamáveis)?'
    const forbiddenDeadline = '7 dias úteis'

    // Act
    const response = await queryAssistant(query)

    // Assert
    expect(response.answer).toMatch(/não.*elegível|não.*processo padrão/i)
    expect(response.answer).not.toContain(forbiddenDeadline)
    expect(response.source).toContain('POL-001')
  })
})
```

**Why this is correct:**
- `it(...)` describes exact behavior — failure is self-documenting
- `.toMatch(...)` verifies specific guardrail content
- `.not.toContain(forbiddenDeadline)` verifies the rule was NOT inverted
- `.toContain('POL-001')` verifies source citation
- Domain data: ANTT class 3, POL-001, actual deadline string from the document

---

## DO — Example 2: SLA lookup (correct tier)

```javascript
describe('queryAssistant', () => {
  it('returns Gold critical incident SLA values with SLA-2024 citation', async () => {
    // Arrange
    const query = 'Qual o SLA de incidente crítico para cliente Gold?'

    // Act
    const response = await queryAssistant(query)

    // Assert
    expect(response.answer).toContain('30')       // 30 min first response (SLA-2024 §2)
    expect(response.answer).toContain('4h')       // 4h resolution (SLA-2024 §2)
    expect(response.source).toContain('SLA-2024')
  })
})
```

**Why this is correct:**
- Values `'30'` and `'4h'` are from SLA-2024 §2 — not invented
- Two assertions cover two specific values in the same response
- Source citation asserted separately

## DON'T — Anti-patterns with real consequences

### Anti-pattern 1: `toBeDefined()` as sole assertion

```javascript
// ❌ WRONG — passes for empty string "", null, or completely wrong answer
it('test query', async () => {
  const result = await queryAssistant('return policy')
  expect(result).toBeDefined()
})
```

**Consequence:** This test would pass even if the assistant returned `""`, `null`, or `"O prazo é 30 dias"` (wrong value). It provides zero confidence in the behavior.

**Fix:** Use `.toContain('7 dias úteis')` and `.toContain('POL-001')`.

---

### Anti-pattern 2: Spying on internals (testing implementation, not behavior)

```javascript
// ❌ WRONG — breaks on any internal refactor; tests HOW, not WHAT
it('calls vector store', async () => {
  const spy = jest.spyOn(vectorStore, 'search')
  await queryAssistant('SLA Gold')
  expect(spy).toHaveBeenCalled()
})
```

**Consequence:** The test will break every time internal implementation changes (even when behavior is correct), and will pass even if the answer returned is wrong. It tests plumbing, not correctness.

**Fix:** Assert the final response content and source citation.

---

### Anti-pattern 3: Permissive mock that hides real behavior

```javascript
// ❌ WRONG — mock returns the "right" answer regardless of the real pipeline
jest.mock('../rag-pipeline', () => ({
  query: () => ({ answer: '7 dias úteis', source: 'POL-001' })
}))
it('returns return deadline', async () => {
  const result = await queryAssistant('prazo de devolução')
  expect(result.answer).toContain('7 dias úteis')
})
```

**Consequence:** This test always passes — even if the real RAG pipeline is broken, returns the wrong document, or halluccinates. The mock bypasses the entire component being tested.

**Fix:** Integration tests must call the real pipeline. Mock only external services at the boundary (e.g., the LLM API in unit tests).

---

### Anti-pattern 4: Generic test data (placeholder inputs)

```javascript
// ❌ WRONG — 'hello' is not a NovaTech domain query; test proves nothing about the domain
it('test query', async () => {
  const result = await queryAssistant('hello')
  expect(result).toBeDefined()
})
```

**Consequence:** Even if the test passes, it says nothing about whether the assistant handles real NovaTech scenarios correctly. Guardrails, SLA values, and freight multipliers are never exercised.

**Fix:** Use queries from the NovaTech domain: `'Qual o prazo de devolução?'`, `'SLA Gold incidente crítico?'`, `'Multiplicador Norte 600kg?'`.

## Quick Checklist (< 2 min before committing any test)

- [ ] **Naming:** Does the `it(...)` description describe specific behavior without reading the body?
- [ ] **AAA labeled:** Are `// Arrange`, `// Act`, `// Assert` all present?
- [ ] **One Act:** Is there exactly one `await` in the Act section?
- [ ] **Behavioral assertion:** Is there at least one `.toContain()` / `.toMatch()` / `.toBe()`?
- [ ] **No sole `toBeDefined()`:** Is `toBeDefined()` NOT the only assertion?
- [ ] **Domain data:** Is the input a real NovaTech query (not `'test'` / `'hello'`)?
- [ ] **Source cited:** Does the test assert `expect(response.source).toContain('...')`?
- [ ] **Guardrail tests include `.not`:** For guardrail scenarios, is there a `.not.toContain(forbiddenValue)`?
